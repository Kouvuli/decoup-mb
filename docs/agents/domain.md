# Domain docs

Use one root CONTEXT.md glossary and docs/adr/ for architectural decisions. A single native app does not need a context map. Read relevant terms and ADRs before exploring/changing domain code. The initial glossary reuses the agreed DecoUp terms; later shared changes need cross-repo coordination, not silent copying.

Requirements and HLD/LLD/data modelling belong in the configured decoup-specs checkout. Architecture belongs in docs/ARCHITECTURE.md. Do not copy full canonical requirements into local glossary or research notes.
